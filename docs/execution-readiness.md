# QQQ / US100 离线执行演练

新增执行模块只用于 FakeBroker 演练，`live_enabled` 固定为 `false`。它没有网络、签名、真实凭据或交易接口；现有 paper 策略和行情客户端不接入这个模块。不能据此宣称实盘已就绪。

在项目目录运行一条命令：

```powershell
python -m variational_grid.execution_drill
```

命令只创建临时目录，结束后删除，输出 JSON 故障检查结果。它不读取现有配置、会话、行情输出或账本。FakeBroker 在同一次演练中保留内存，用来模拟客户端重启时交易所订单仍存在；没有宣称重启了真实交易所。

## 已实现的执行边界

- `ExecutionJournal` 使用单 writer 锁、SQLite WAL 与 `synchronous=FULL`，拒绝复用其他 SQLite 账本或非数据库文件。稳定 intent key、完整订单参数、稳定 client id 在调用 broker 前提交。相同 key 相同参数只返回已存订单；同 key 不同参数拒绝。
- 状态包括 `sending`、`ack`、`partial`、`cancel_pending`、`canceled`、`filled`、`rejected`、`unknown`。发送或撤单结果不明进入 `unknown`，保留数量预留，不自动重发。撤单请求独立持久记录，部分成交不会使其再次可撤。
- 启动必须先对账本地订单、远端订单、逐笔成交、累计数量与仓位。远端孤儿单、未知订单查询缺失、身份不符或仓位不符均禁止新增风险。缺失订单不能作为“未提交”的证据。
- 成交按 venue 与 trade id 去重，重复 id 的内容必须一致；允许逐笔报告时间乱序，累计不能倒退或超量。撤单期间的成交仍记账，过时回报不使终态回到 open。资金与数量计算采用 Decimal。
- `RiskLimits` 必须显式提供单笔、单品种仓位、总名义金额、未对冲名义金额、保证金和时效预算。未成交开仓也占用仓位及保证金预算；未对冲预算按任一侧可独立成交的保守情况计算，待执行减仓也可能移除对冲。
- `reduce_only` 必须与已确认仓位反向，总量不得超过扣除所有待确认减仓后的仓位；部分成交、撤单中和 unknown 的剩余数量继续预留。减仓仍校验身份、行情时效、单笔限额和未对冲上限；价格变化使既有敞口超限后，允许不扩大提交前最坏敞口的减仓，移除对冲而扩大最坏敞口仍拒绝。它不增加初始保证金预留。
- 单腿拒单和结果不明会持久锁定新增风险；完成对账后还需显式 `resume_new_risk()`。持久紧停允许满足上述校验的减仓，清除紧停后必须重新对账；不会自动撤销订单或把仓位当作已经平掉。

演练中的保证金按显式 `initial_margin_fraction` 估算，输入 `available_margin_usdc` 表示扣除现有仓位需求后、尚未扣除本地未完成订单预留的模拟可用额。这不是任何交易所的保证金算法。演练只支持线性名义金额、美元 beta=1 的 QQQ/US100 示例，不处理资金费、股息或真实强平。样例金额不是批准的实盘预算。

## 实盘接入仍需确定

Variational 计划使用前端 `vr-token` 会话交易，不以公开 API key 为前提。当前模块只验证本地模拟状态机，不能猜测前端交易 endpoint 或扩大已有行情白名单。需要先核对实际前端协议和官方允许的使用方式：

1. firm quote 与 indicative quote 的差别、有效期、接受动作、数量/价格绑定及成交承诺；报价权限与交易权限如何隔离。
2. client id 是否受支持，重复提交语义、按 id 查询及订单暂时查不到时的最终确认方法；没有可靠幂等/对账协议就保持停止。
3. 订单、撤单、逐笔成交、累计成交、仓位与账户身份的真实 schema；确认分页、重连补数、部分成交及撤单竞态语义。
4. `401/403` 后权限变化、会话刷新与撤销；`429`、超时、连接中断后如何查询原请求，不能将网络错误解释为未下单。
5. 两 venue 的余额、可用/占用保证金、订单预留、reduce-only 约束、强平与最大仓位。真实账户、订单限额、未对冲上限及紧停处置须由用户显式设置。

浏览器令牌更新、行情读取和未来交易执行应是独立能力。模拟演练不证明当前 vr-token 只读，也不为它增加交易权限。
